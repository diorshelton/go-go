cache/store.go — RWMutex KV Store

The cache is the simplest component in terms of code, and the most important in terms of correctness. Every design decision here comes directly from Module 3.

The complete implementation

package cache import ( "encoding/json" "sync" ) type Store struct { mu sync.RWMutex data map[string]json.RawMessage } func New() *Store { return &Store{data: make(map[string]json.RawMessage)} } func (s *Store) Get(key string) (json.RawMessage, bool) { s.mu.RLock() defer s.mu.RUnlock() v, ok := s.data[key] return v, ok } func (s *Store) Set(key string, val json.RawMessage) { s.mu.Lock() defer s.mu.Unlock() s.data[key] = val } func (s *Store) Delete(key string) { s.mu.Lock() defer s.mu.Unlock() delete(s.data, key) } func (s *Store) Keys() []string { s.mu.RLock() defer s.mu.RUnlock() keys := make([]string, 0, len(s.data)) for k := range s.data { keys = append(keys, k) } return keys }

This is the entire store. 40 lines including imports. Its simplicity is intentional — complexity here would mean correctness risk. The contract is clear:

  • Get and Keys: read lock (concurrent-safe)
  • Set and Delete: write lock (exclusive)
  • All methods operate on a pointer receiver (*Store) — the mutex is never copied
  • All unlocks are deferred — panics don't leave locks held

Testing it

The store's tests should exercise both correctness and concurrency:

func TestStore(t *testing.T) { s := cache.New() // Set and Get s.Set("foo", json.RawMessage(`"bar"`)) val, ok := s.Get("foo") if !ok || string(val) != `"bar"` { t.Fail() } // Delete s.Delete("foo") _, ok = s.Get("foo") if ok { t.Fatal("expected key to be deleted") } } func TestStoreConcurrent(t *testing.T) { s := cache.New() var wg sync.WaitGroup for i := 0; i < 100; i++ { wg.Add(2) go func(n int) { defer wg.Done() s.Set(fmt.Sprintf("k%d", n), json.RawMessage(`1`)) }(i) go func(n int) { defer wg.Done() s.Get(fmt.Sprintf("k%d", n)) }(i) } wg.Wait() }

Run with go test -race ./cache/.... If the race detector doesn't fire, your locking is correct.
