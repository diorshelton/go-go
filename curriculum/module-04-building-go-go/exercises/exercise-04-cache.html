Implement cache/store.go

The simplest file in the codebase, and the one where correctness matters most. Every design choice follows directly from what you learned in Module 3.

Locking rules — commit these to memory

Get(key)
RLock / RUnlock
Read-only. Multiple goroutines can read concurrently — no writer blocked.
Keys()
RLock / RUnlock
Iteration is read-only. Concurrent reads still safe.
Set(key, val)
Lock / Unlock
Mutation. Exclusive — no readers or writers during this call.
Delete(key)
Lock / Unlock
Mutation. Same — must be exclusive.

Implement the Store

Create cache/store.go in package cache. The struct has two fields: mu sync.RWMutex and data map[string]json.RawMessage. Implement all four methods. Rules for every method:

  • Always use a pointer receiver (*Store) — never copy the mutex
  • Always use defer to unlock — panics don't leave locks held
  • Never hold the lock while doing I/O, network calls, or anything slow
json.RawMessage is just []byte
json.RawMessage is a type alias for []byte. Storing it means storing the raw JSON bytes exactly as received. When you return it from Get, the router writes those bytes directly as the response body — no encoding, no decoding, no transformation. This is the right design for a cache.

Write the concurrent test

func TestStoreConcurrent(t *testing.T) { s := cache.New() var wg sync.WaitGroup for i := 0; i < 100; i++ { wg.Add(2) go func(n int) { defer wg.Done() s.Set(fmt.Sprintf("k%d", n), json.RawMessage(`1`)) }(i) go func(n int) { defer wg.Done() s.Get(fmt.Sprintf("k%d", n)) }(i) } wg.Wait() }

Run it with: go test -race ./cache/...

If the race detector fires, your locking is wrong. If it passes, your store is correct under concurrent load.
