The Request Line

The first line of every HTTP request tells the server three things: what action to perform, on what resource, and which protocol version to use. Your parser reads this line first — and if it's malformed, the answer is always 400.

What it looks like on the wire

When a client sends an HTTP request, the first bytes that arrive on your TCP connection look like this:

GET /keys/foo HTTP/1.1\r\n Host: localhost:8080\r\n \r\n

That first line — GET /keys/foo HTTP/1.1\r\n — is the request line. Three parts, separated by single spaces, terminated by CRLF (\r\n). Nothing else is valid.

GET
Method — the action to perform. In go-go: GET, PUT, DELETE. Case-sensitive, always uppercase.
/keys/foo
Request target — the resource path. Starts with /. May include a query string (?key=value), though go-go doesn't use one.
HTTP/1.1
Protocol version — always HTTP/1.1 for go-go. Your parser should reject anything else with 400 or 505.
\r\n
CRLF terminator — carriage return + line feed. Every line in an HTTP message ends this way. \n alone is not valid (though many parsers accept it for resilience).

Parsing it in Go

The parsing strategy: read one line from the connection, split on spaces, validate each part.

// reader wraps the conn with buffering for line-by-line reads reader := bufio.NewReader(conn) line, err := reader.ReadString('\n') if err != nil { writeError(conn, 400, "Bad Request") return } line = strings.TrimRight(line, "\r\n") parts := strings.SplitN(line, " ", 3) if len(parts) != 3 { writeError(conn, 400, "Bad Request") return } method, path, version := parts[0], parts[1], parts[2]

A few things to note:

  • bufio.NewReader wraps the raw connection. It buffers reads internally, which makes line-by-line parsing efficient.
  • ReadString('\n') reads until it finds a newline. The result includes the \n, so you strip it (and the \r) with TrimRight.
  • SplitN(line, " ", 3) splits on spaces but caps at 3 parts — important because a path could theoretically contain spaces (encoded, but still).
Why bufio.Reader?
net.Conn.Read() reads raw bytes into a buffer — you might get 1 byte, or 100, depending on what arrived. Finding "the end of a line" in raw bytes requires you to scan byte by byte. bufio.Reader handles that efficiently with an internal buffer. In go-go, you create one bufio.Reader per connection and use it for the entire request (and subsequent requests on keep-alive connections).

Validation: what to reject

A defensive parser rejects anything that doesn't match the spec:

  • Fewer than 3 parts: 400 Bad Request
  • Unknown method: 405 Method Not Allowed (or 400 — pick one and be consistent)
  • Path doesn't start with /: 400 Bad Request
  • Version isn't HTTP/1.1: 400 Bad Request or 505 HTTP Version Not Supported
Never panic on bad input
If parts[0] is an unknown method, return 400 — don't crash. Your parser is the outermost defense layer. Any malformed input at any stage must result in a clean 4xx response, not a panicking goroutine.
Think it through
Why is SplitN(line, " ", 3) safer than Split(line, " ") for parsing the request line?
Consider a request like: GET /my path HTTP/1.1 — what would each produce?
SplitN limits the number of parts. Split(line, " ") would produce ["GET", "/my", "path", "HTTP/1.1"] — four parts, and your length check would reject it as malformed, even though it might be a valid-ish request. SplitN(line, " ", 3) produces ["GET", "/my path", "HTTP/1.1"] — three parts, with the path preserved including its space. The path is the middle component and should absorb any remaining content.
Think it through
What should happen if ReadString('\n') returns an error before finding a newline?
This happens if the client disconnects mid-send, or sends a very long line, or the connection times out. What's the right response?
Return 400 and close the connection. If you can't read a complete request line, you don't have enough information to route or respond correctly. Write a 400 response (if you can — the connection might already be dead), close the connection, and let the worker pick up the next one from the channel. Don't retry. Don't block. Don't panic.
